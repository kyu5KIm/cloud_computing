# 오른쪽 학습 질문 챗봇 — 2026-10-18

모든 화면의 오른쪽 아래 ‘학습 질문’ 버튼으로 열고 닫는 패널이다. 열면 오른쪽 공간을 확보하여 학습 본문을 덮지 않고 키워드·메모 칸을 숨긴다. 닫으면 원래 칸을 복원한다. 좁은 화면은 패널과 본문을 위아래로 배치한다. Enter로 전송, Shift+Enter로 줄바꿈하며 한글 조합 중 Enter는 전송하지 않는다.

현재 챕터 자동 선택, 전체 7강의, 우선 참고할 개별 챕터를 선택할 수 있다. **챕터 선택은 우선순위이며 검색을 제한하지 않는다.** 예를 들어 C02-2에서 CAF를 물어도 C02-1의 도입 프레임워크를 찾아 설명한다. 닫거나 화면을 옮겨도 탭 내 질문·대화를 유지한다. 새로고침·새 대화는 화면 대화를 초기화한다. 서버는 중복 요청·진행 상태를 위해 최대 30개 요청을 메모리에 유지하며 재시작 시 사라진다. 파일·학습 진도 저장소에는 대화를 기록하지 않는다.

## 요청과 근거

`브라우저 → 동일 origin /api/chat/jobs → 범위 검사 → 사이트의 확인된 개념·과정·보충설명 검색 → Codex CLI → JSONL/출처 검증 → 패널`

- 일상·날씨·식사 추천 등 명확한 범위 밖 요청은 서버에서 거부하고 모델을 호출하지 않는다. 이전 학습 질문의 ‘더 쉽게’ 같은 후속 질문은 허용한다. 단순 범위 규칙은 완전한 의미 분류기가 아니므로 근거 제한 지시와 결과 scope 검사도 적용한다.
- 현재 화면의 비공개 답안·메모·시험 작성 내용을 자동으로 읽어 보내지 않는다. 사용자가 전송한 질문, 최근 최대 6개 메시지, 우선 챕터와 전체 강의의 관련 수업 근거·버전만 전달한다.
- DataCamp 확인 내용과 자체 재구성, 외부 공식 보충설명을 입력에서 구분한다. 최신 가격·법규·지원 사양은 수업 근거만으로 확정하지 않는다. 모델의 출처 ID는 서버가 전송한 목록 안에서 검증한다.
- 답변은 일반 텍스트로 이스케이프하여 표시하고 등록된 출처의 링크만 붙인다. 응답 HTML·임의 링크·명령을 실행하지 않는다.

## 모델·인증·실행 경계

고정 모델은 `gpt-6.1-sol`, 추론 강도는 `low`(화면의 Light)다. API 키·모델 자동 전환·자동 재시도는 없다. 매 전송에 공식 `login status`가 ChatGPT 인증인지 검사하고 실행에도 `forced_login_method="chatgpt"`를 고정한다. 자격증명 파일을 읽거나 복사하지 않는다.

검증한 실행 버전은 Windows `0.163.0-alpha.10.2`다. 설치 경로를 탐색하되 정확히 그 버전만 선택하고 요청 시 다시 검사한다. 버전 변경은 재검증 전 차단한다. 실행 인수는 서버 고정, 질문은 stdin 데이터, `shell:false`, 비밀·provider 관련 환경변수는 상속하지 않는다.

- 임시 디렉터리에 비어 있는 Git 저장소와 고정 정책·응답 스키마만 준비한다. 프로젝트나 개인 자료를 작업 폴더에 복사하지 않는다. 정리 시 임시 루트와 접두사를 확인한다.
- `--no-daemon`, `--ignore-user-config`, `--ignore-rules`, `--ephemeral`, `--sandbox read-only`를 사용한다. 셸·앱·플러그인·브라우저·컴퓨터·Code Mode 호스트·다중 에이전트·검색 등 실행 기능을 고정 인수로 비활성화한다. 웹 검색도 비활성화하고 호스트 스킬 탐색을 생략한다.
- 프롬프트의 ‘도구 금지’만을 보안 경계로 삼지 않는다. 비활성화 인수·호스트 차단·외부 설정 미상속을 함께 사용하며, 결과에 명령·MCP·파일 변경 등 실행 이벤트가 나오면 실패로 처리한다. 사후 이벤트 검증 자체가 이미 실행된 작업을 되돌리는 통제는 아니다.
- 위 설정은 이 버전의 질문 전용 경로다. read-only 하나로 호스트의 모든 읽기·네트워크가 격리되었다고 주장하지 않는다. CLI의 managed 설정·새 도구·버전이 바뀌면 경계를 재검토한다. 기존 시험 자동 채점 실행기는 계속 차단 상태다.
- 최대 입력 4,000자, 최근 대화 6개, 동시 1개, 서버 실행 상한 30개, 실행 제한 120초다. 취소·제한 시간에는 Windows 프로세스 트리 종료를 요청한다. 이미 발생한 계정 사용량의 복원을 보장하지 않는다.
- JSONL 성공 종료·turn 완료·답변 JSON·허용된 출처를 모두 확인한다. 시작 전의 알려진 개발 기능/비활성 Code Mode 진단만 구분하며 다른 오류를 정상 답변으로 숨기지 않는다.

## 검증 기록

자동 테스트 21개 통과: 기존 기능 15개와 챗봇 6개. 일상 질문의 호출 0회, 후속 질문, 범위별 근거, 고정 모델·인수, API 인증·버전 변경 거부, 임시 영역 정리, 잘못된 출처·실행 이벤트·미완료 응답 거부, 중복·동시 요청·취소, 세션·CSRF를 검사했다. 모의 검사는 실제 모델 품질의 보장이 아니다.

실제 Windows CLI 진단에서 ChatGPT 로그인을 확인했고, 학습 질문 호출의 응답을 확인했다. 첫 세 진단 호출은 정상 답변 전 진단 이벤트 때문에 앱 검증이 거부했으며, 원인을 확인하여 알려진 진단만 구분했다. 브라우저에서 ‘수직 확장과 수평 확장의 차이를 두 문장으로’ 요청해 실제 답변과 ‘클라우드의 강점’ 출처를 확인했다. C02-2에서 CAF를 Enter로 질문해 C02-1의 여섯 도입 관점과 출처가 나오는 것을 확인했다. 식사·날씨 질문 거부, Shift+Enter 줄바꿈, 패널 닫기·다시 열기의 대화 유지와 키워드 칸 복원을 확인했다. 본문 오른쪽 640px / 챗봇 왼쪽 664px로 가림이 없고 가로 넘침이 없었다. 검증을 위한 실제 호출은 계정 사용량에 반영된다. 모든 악성 입력·계정 한도 오류의 실환경 검증이나 OS 전체 침투 테스트를 완료했다는 뜻은 아니다.
